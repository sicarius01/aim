# Aim Trainer

winsafe(Win32 API) 기반의 가벼운 개인용 에임 연습 프로그램입니다. 외부 GUI 프레임워크 없이
순수 Win32 + 직접 GDI 페인팅 + raw mouse input으로 동작합니다. 창 제목은 `Notes`,
외관은 VSCode 다크 그레이 톤이라 눈에 잘 띄지 않습니다.

## 모드

우측 상단 **모드 버튼**을 클릭하면 순환합니다:

- **클릭 · 정적 다중** — 랜덤 위치 타깃을 좌클릭으로 제거 (반응속도/플릭/타깃 스위칭)
- **트래킹 · 스트레이프** — 좌우로 랜덤 반전하는 타깃 추적 (오버워치 트래킹 핵심)
- **트래킹 · 에어** — 수평 왕복 + 수직 사인 부유 (파라/공중 타깃)
- **트래킹 · 트레이서(블링크)** — 주기적으로 순간이동하는 타깃 재포착
- **트래킹 · 파라(아크)** — 느리고 큰 아크를 그리는 타깃
- **트래킹 · 겐지(대시)** — 정지 후 빠른 직선 버스트

트래킹 모드는 **좌클릭을 누른 채** 초록 링을 타깃에 유지 → **추적 정확도%**로 점수.

## 기능

- **초록 빈 링 커서**: 연습 중 OS 커서는 숨겨지고 에임 영역에 갇히며, 두께 있는 초록 빈 원으로 표시.
- **게임 정확 감도**: raw mouse input(가속 무시) + 게임 yaw + 모니터 픽셀/° → cm/360을 게임과 맞춤.
- **기록**: 점수 · 최고 점수(영구 저장) · 정확도 · 반응속도(평균/최고) · 중앙 정확도 · 추적%.
- **히트맵**: 클릭 위치 분포 오버레이 토글(명중=초록, 빗맞힘=빨강)로 조준 편향 확인.
- **진행 스파크라인**: 최근 라운드 점수 추이를 에임 영역 좌상단에 표시.
- **CSV 자동 로그**: 라운드(2초+)마다 `aim_log.csv`에 시각·모드·시간·점수·정확도 기록.

## 빌드 / 실행

```sh
cargo build --release
./target/release/aim_trainer.exe
```

요구 사항: Rust(MSVC 툴체인), Windows.

## 사용법

1. 우측 패널에서 설정값을 입력합니다.
2. **[시작]** 버튼 또는 **F2**로 연습을 시작합니다.
   - 커서가 초록 링으로 바뀌고 에임 영역에 갇힙니다.
3. 초록 링으로 타깃을 조준해 **좌클릭**합니다.
4. **ESC**(또는 F2, 또는 [정지])로 멈춥니다. 다른 창으로 전환(Alt-Tab)해도 자동으로 멈춰
   커서가 복구됩니다.

## 설정 항목

| 항목 | 설명 | 기본값 |
|------|------|--------|
| 마우스 DPI | 마우스 하드웨어 DPI | 800 |
| 감도 (오버워치 인게임) | 오버워치 설정의 감도 값. 캐릭터별로 바꿔 입력 | 5.0 (4~6) |
| 게임 yaw | 감도 1.0당 회전 각도(°/카운트). **오버워치 0.0066**, CS·Apex 0.022, 발로란트 0.07 | 0.0066 |
| eDPI | `DPI × 감도` (표시 전용) | 4000 |
| cm/360 | 한 바퀴(360°) 도는 데 필요한 마우스 이동 거리 (표시 전용) | ≈34.6 cm |
| 커서 속도 배율 | 미세 보정 (1.0 기준) | 1.0 |
| 타깃 크기 | 원의 반지름(px) | 28 |
| 생성 주기 | 새 타깃 생성 간격(ms) | 850 |
| 타깃 수명 | 생성 후 사라지기까지(ms) | 1100 |
| 최대 동시 타깃 | 화면에 동시에 떠 있는 최대 개수 | 4 |

설정은 **[시작]을 누르는 순간** 적용됩니다(연습 중에는 고정).

## 감도 동작 방식 (게임 정확 모델)

실제 3D 게임에서 마우스 감도는 "1카운트당 화면 픽셀"이 아니라 **"1카운트당 회전 각도"**(yaw × 감도)를
결정합니다. 화면 픽셀 이동량은 FOV와 화면 위치에 따라 달라집니다. KovaaK's·Aim Lab 같은 진짜
에임 트레이너가 이 방식을 씁니다. 이 프로그램도 같은 모델을 따릅니다:

```
수평FOV  = 2·atan(tan(수직FOV/2) × 화면가로/화면세로)      # 수직FOV 103°(오버워치 기본)
픽셀/°   = 화면가로(px) / 수평FOV                          # ★사용자 모니터 전체 기준★
픽셀_이동 = 마우스_카운트 × (감도 × yaw) × 픽셀/° × 커서_속도_배율
cm/360   = (360 × 2.54) / (DPI × 감도 × yaw)
```

핵심: **픽셀/°는 작은 에임 영역이 아니라 사용자 모니터 전체**를 기준으로 잡습니다. 손은 게임 화면
픽셀 밀도에 길들여져 있으므로, 모니터 해상도(`GetSystemMetrics`로 자동 감지)에 맞춰야 손맛이
동일해집니다. (1920×1080·오버워치 800 DPI·감도 5.0 → 마우스 1cm당 커서 ≈151px = 게임과 동일.)
**cm/360 값을 본인 게임 값에 맞추면** 감도가 그대로 전이됩니다.

- **DPI는 커서 속도(ppc)에 직접 들어가지 않습니다.** raw 카운트가 이미 하드웨어 DPI를 반영하기
  때문입니다(게임 eDPI 불변성과 동일). DPI 칸은 eDPI·cm/360 표시 계산에만 쓰이며, **실제 마우스
  DPI와 일치**시켜야 표시가 정확합니다.

> 정확한 연습을 위해 Windows 설정 → 마우스 → 추가 마우스 설정 → 포인터 옵션에서
> **"포인터 정확도 향상"(마우스 가속)을 끄는 것**을 권장합니다. raw input 자체는 가속의
> 영향을 받지 않지만, 평소 게임 환경과 일치시키기 위함입니다.

## 점수 계산

타깃을 맞히면:

```
정확도   = clamp(1 − (클릭~중앙 거리 / 반지름), 0, 1)      # 중앙=1, 가장자리=0
신속도   = clamp(1 − (반응시간 / 타깃수명), 0, 1)          # 즉시=1, 소멸직전=0
획득점수 = 100 × (0.25 + 0.75 × 정확도) × (0.35 + 0.65 × 신속도)
```

- 타깃 없는 곳을 클릭하면 **빗맞힘**으로 −10점(최저 0).
- 클릭하지 못하고 사라진 타깃은 **놓침**으로 집계됩니다.
- 기록: 점수 / 명중(놓침·빗맞힘) / 클릭 정확도 / 평균·최고 반응속도 / 평균 중앙 정확도.

## 렌더링 아키텍처 (vsync 페이싱)

Win32에서 `WM_PAINT`·`WM_TIMER`는 **메시지 큐가 비었을 때만** 생성되는 최저 우선순위 메시지라,
마우스를 빠르게 움직여 `WM_INPUT`이 큐를 가득 채우면 리페인트가 **굶어 죽어(starvation)** 커서가
뚝뚝 끊깁니다. 그래서 타이머 기반 렌더를 버리고 **게임 방식의 vsync 페이싱**을 씁니다:

- 별도 **페이서 스레드**가 `DwmFlush()`로 다음 수직동기(vblank)까지 **블록(잠듦)** → busy-wait 아님,
  유휴 시 CPU ≈ 0%.
- 매 vblank마다 UI 스레드에 `WM_APP` 프레임 메시지를 `PostMessage` → UI는 그 메시지에서 한 프레임을
  `InvalidateRect`+`UpdateWindow`로 **동기 렌더**. `WM_APP`은 일반 우선순위라 `WM_INPUT`에 굶지 않음.
- 결과: **모니터 주사율 그대로**(144Hz→144fps, 240Hz→240fps) 렌더, 커서가 끊김 없이 연속적.
- 입력(`WM_INPUT`)은 매 이벤트마다 가상 커서 위치를 **누적만** 하고(렌더는 프레임이 담당), 라이브러리
  `run_main`(GetMessage 루프)은 그대로 둡니다.

## 구현 메모

- `winsafe` 0.0.27에는 raw input 래퍼가 없어 `RegisterRawInputDevices` / `GetRawInputData` /
  `PostMessageW` / `DwmFlush`를 직접 FFI(`raw` 모듈)했습니다. 마우스 이동은 raw input(가속 무시,
  모든 이벤트 수신 — `WM_INPUT`은 합쳐지지 않고 합쳐져도 델타가 누적되어 손실 없음), 클릭은
  `WM_LBUTTONDOWN` + 가상 커서 좌표로 판정합니다.
- 에임 영역은 더블 버퍼링(메모리 DC + 비트맵 → `BitBlt`)으로 깜빡임 없이 그립니다.
- 다크 테마는 `WM_CTLCOLORSTATIC`/`WM_CTLCOLOREDIT` 처리로 구현했습니다.
